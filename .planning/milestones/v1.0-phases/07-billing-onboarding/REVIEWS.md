## Review 2: Data Flow & UX Focus

### Critical Bugs

**1. Data Flow Mismatch - Inngest Function (BROKEN)**

`handlers.ts` sends:
```
{ contractorId, customerId, subscriptionId, invoiceId }
```

`stripe-payment-failure.ts` expects:
```
{ contractorId, stripeCustomerId, failureReason }
```

Field names don't match: `customerId` vs `stripeCustomerId`. **This Inngest function will fail silently.**

**2. Test Call Verification Gating - Bypassed**

`OnboardingWizard.tsx` footer "Complete Setup" button calls `handleComplete()` without checking if test call was detected. Users can bypass verification.

### Missing Functionality

**3. No Database Update on Test Call Verification**

No `go_live`, `agent_active`, or similar flag is set in the `contractors` table after verification.

**4. No Price ID Configuration**

`createCheckoutSession()` requires `priceId` but no environment variable mapping exists.

### Working Correctly

- Webhook signature validation
- Stripe keys server-only
- Customer Portal correctly wired
- Realtime detection with polling fallback

## Recommended Fix

Align data sent in `handlers.ts` with what `stripe-payment-failure.ts` expects:

```typescript
// In handlers.ts, change line ~128:
await inngest.send({
  name: 'stripe/payment.failed',
  data: {
    contractorId,
    stripeCustomerId: customerId,  // <-- rename
    failureReason: undefined,       // <-- add (or derive from invoice)
    subscriptionId,
    invoiceId,
  },
})
```

And/or update `stripe-payment-failure.ts` to accept the field names actually sent.
