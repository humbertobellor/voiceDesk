## Overview

VoiceDesk v1.0 is a 24/7 AI phone receptionist SaaS for independent home-service contractors (HVAC, plumbing, electrical). A contractor can sign up, configure their AI receptionist, receive a dedicated Twilio/Retell phone number, and immediately start capturing leads, booking Google Calendar appointments, and receiving real-time SMS/WhatsApp/Telegram notifications — with Stripe billing collecting revenue from day one.

The build went from zero to production in 21 days, completing 11 phases and 55 plans. Two phases (10 and 11) were inserted after the original 8-phase roadmap to close audit gaps discovered before the v1.0 milestone.

## Milestone Summary

**Inserted Phases:**

- Phase 10: Notification settings form — sms_number + whatsapp_number write UI (inserted after Phase 9 to close NOTIF-01, NOTIF-02, EMRG-03, PORTAL-04 audit gaps)
- Phase 11: Account page subscription load fix + BILL-03 deactivation (inserted after Phase 10 to close BILL-02, BILL-03 audit gaps)

**Key Decisions:**

- Retell managed Twilio integration (not raw TwiML/SIP)
- Webhook-first architecture — all business logic in call_ended / call_analyzed handlers
- `after()` from `next/server` for non-blocking webhook processing (NOT `@vercel/functions`)
- AES-256-GCM encryption of all Google OAuth tokens before Supabase write
- Hard-coded gas smell / CO alarm keywords bypass all LLM calls (EMRG-02 non-overridable)
- booking_conflict on leads table (not appointments) — UNIQUE constraint makes second appointment row impossible
- 14-day trial with payment_method_collection='if_required' (card optional at trial start)
- Stripe API version 2026-04-22.dahlia
- Promise.allSettled mandatory for multi-channel notification dispatch
- notification_log row written before send (pending-before-send pattern)
- Retell v2 LLM-first: create LLM first, then Agent referencing LLM ID
- Haitian Creole removed (D-01) — not supported by Retell native ASR/TTS
- is_active boolean for deactivation state (replaces agent_sync_status hack)
- Wave 0 stub pattern: test files import future modules; stubs throw "not yet implemented" for correct TDD RED flow

**Issues Resolved:**

- IDOR vulnerability in Stripe webhook handler (07-07 gap closure)
- Tier mapping bug where all plans mapped to wrong Stripe tier (07-07)
- NOTIF-01/NOTIF-02: no UI to set sms_number/whatsapp_number (Phase 10)
- BILL-02: useState/useEffect subscription load bug in account page (Phase 11)
- BILL-03: deactivation not storing is_active flag properly (Phase 11)
- Missing Telegram bot name — VoiceDeskBot → voiceDeskTelBot (Phase 9)
- 05-05-SUMMARY.md missing at milestone close — written retroactively

**Issues Deferred:**

- NOTIF-03 (partial): Telegram bot registration with @BotFather + setWebhook call is an operational step, not automated
- EMRG-01 (partial): Live call emergency path unverifiable without real Retell traffic; logic verified by unit tests
- BILL-03 (partial): Retell agent cannot be deactivated via API (SDK limitation) — only is_active flag gates calls
- D-07: caller_name never populated by Retell webhooks — SMS notifications include phone but not name
- WhatsApp WABA approval pending — WHATSAPP_CONTENT_SIDS have placeholder values until Meta approves templates
- Google OAuth app must be moved to production mode before first beta contractor connects (exits "testing" mode 7-day token expiry)

**Technical Debt Incurred:**

- WHATSAPP_CONTENT_SIDS constants hardcoded as HXplaceholder_* — must update after WABA approval
- Haitian Creole language option removed entirely — may need custom LLM endpoint if market demand confirmed
- Recording retention policy not enforced in DB — no TTL/purge job implemented
- CASA Tier 2 security assessment required for calendar.events scope before public launch (3–8 week process)
- RLS policies use `(SELECT auth.uid())` wrapper (40 occurrences) — correct pattern but needs documentation for future maintainers
