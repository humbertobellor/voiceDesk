
    **Change 2 — `handleSubscriptionUpdated`: D-10 reactivation with is_active guard (D-11)**

    In `handleSubscriptionUpdated`, update the contractor lookup (currently line 215-228) to also select `is_active`:
    ```
    .select('id, is_active')
    ```

    The existing "find contractor by stripe_customer_id" query currently selects only `'id'`. Expand it to `'id, is_active'`.

    After the existing `db.from('contractors').update({ subscription_status: internalStatus, ... })` call, add the reactivation branch:

    ```
    if (internalStatus === 'active' && contractor.is_active === false) {
      // D-10: Auto-reactivation — set is_active = true
      await db.from('contractors').update({ is_active: true }).eq('id', contractorId)
      console.log('[webhook/stripe] contractor ${contractorId} reactivated: is_active set to true')

      // D-11: Re-link Retell agent only if both IDs present
      const { data: contractorFull } = await db
        .from('contractors')
        .select('retell_agent_id, twilio_number')
        .eq('id', contractorId)
        .single()

      if (contractorFull?.retell_agent_id && contractorFull?.twilio_number) {
        try {
          const retell = getRetellClient()
          await retell.phoneNumber.update(contractorFull.twilio_number, {
            inbound_agents: [{ agent_id: contractorFull.retell_agent_id, weight: 1.0 }],
          })
          console.log('[webhook/stripe] Retell phone ${contractorFull.twilio_number} re-linked on reactivation for contractor ${contractorId}')
        } catch (err) {
          console.error('[webhook/stripe] Retell re-link on reactivation failed for contractor ${contractorId}:', err instanceof Error ? err.message : err)
        }
      } else {
        console.log('[webhook/stripe] skipping Retell re-link on reactivation for ${contractorId}: missing retell_agent_id or twilio_number')
      }
    }
    ```

    **IMPORTANT:** The existing re-link block that fires for ANY `active` status (lines 241-265) should remain — it was already there for general re-link. The new D-10 reactivation block specifically sets `is_active = true` when transitioning from `is_active = false`. Both blocks can coexist: the existing block handles re-link in general; the D-10 block adds the `is_active` flip for previously deactivated contractors. Alternatively, merge them — but only if you can do so without changing existing behavior for contractors that were never deactivated (`is_active = true`). The safest approach: place the D-10 reactivation block (which includes the `is_active = true` DB write) INSIDE the existing `if (internalStatus === 'active')` block at the beginning, guarded by `contractor.is_active === false`.

    Do NOT remove the existing Retell re-link code. Do NOT change idempotency logic.
