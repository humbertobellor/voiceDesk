<objective>
Two webhook handler changes and one API route change, all Stripe-related:

1. `handleSubscriptionUpdated` — primary path for `trial_ends_at`: when `internalStatus === 'trialing'` and `subscription.trial_end` is non-null, write `trial_ends_at` to contractors. This is reliable because the Subscription object always carries `trial_end` when trialing (D-04).
2. `handleCheckoutCompleted` — secondary/best-effort path: write `trial_ends_at` from `session.subscription_data?.trial_end` only if present (D-04).
3. `handleSubscriptionUpdated` — add guarded reactivation (D-10/D-11): read `is_active` in the contractor lookup; if `wasDeactivated` (is_active===false) AND new status is `active`, execute the D-10 path (set is_active=true + Retell re-link) and skip the existing outer re-link block. If `wasDeactivated` is false, run the outer re-link block as before. This eliminates the double Retell call risk.
4. `/api/stripe/subscription` GET route — include `trial_ends_at` and `is_active` in the response (D-04).

Purpose: trial_ends_at is reliably set via the Subscription object. Contractors who update their payment automatically get `is_active = true` and their Retell agent re-linked — exactly once per event.

Output: Updated `handlers.ts` + updated `subscription/route.ts`.
</objective>
