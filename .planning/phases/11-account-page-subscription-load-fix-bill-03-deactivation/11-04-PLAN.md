<objective>
Apply the `is_active = false` enforcement at two runtime layers (D-09):

1. **Middleware** (`middleware.ts`): when an authenticated contractor with a phone number accesses any `/dashboard` route, check `is_active`; if false, redirect to `/settings/account`. The `/settings/account` page is exempt from the redirect (prevents loop).

2. **Retell webhook handler** (`retell-call-classify.ts`): the `load-contractor` step already fetches the contractor; add `is_active` to the select and return early with a structured log if the contractor is deactivated, preventing phantom lead and appointment creation.

TDD order: Plan 01 created RED test stubs in `retell-call-classify.test.ts`. This plan implements the production code and then fills in the test stubs to make them pass (GREEN).

Purpose: Deactivated contractors cannot access the dashboard and no new business data is created during service suspension.

Output: Updated `middleware.ts` + updated `retell-call-classify.ts` load-contractor step + GREEN tests.
</objective>
