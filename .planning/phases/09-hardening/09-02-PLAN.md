<objective>
Transform settings/phone from a read-only page to a two-state page:
- State A (twilio_number is null): area-code input form + "Provision My Number" button
- State B (twilio_number is set): existing number display + forwarding instructions

The provisioning call hits the existing POST /api/provisioning/create endpoint, which already handles Retell agent creation, DB write, and 409 idempotency. The page adds no new API logic.

Purpose: ONBOARD-01 — contractors must be able to self-serve provision their number from settings without visiting the legacy /setup/phone flow.

    ```
    async function handleProvision() {
      if (!areaCode.match(/^\d{3}$/)) {
        setProvisionError('Enter a valid 3-digit area code.')
        return
      }
      setIsProvisioning(true)
      setProvisionError(null)
      try {
        const res = await fetch('/api/provisioning/create', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({ area_code: areaCode }),
        })
        if (res.ok) {
          const data = await res.json()
          setTwilioNumber(data.twilio_number)
          router.refresh()   // Triggers layout re-run so Sidebar picks up new number
          return
        }
        const json = await res.json().catch(() => ({}))
        if (res.status === 409) {
          setProvisionError('Number already provisioned — refresh page.')
        } else if (res.status === 422) {
          setProvisionError('Area code unavailable. Try: 786, 954, or 561.')
        } else {
          setProvisionError(json.error ?? 'Provisioning failed. Please try again.')
        }
      } catch {
        setProvisionError('Network error. Please try again.')
      } finally {
        setIsProvisioning(false)
      }
    }
    ```
