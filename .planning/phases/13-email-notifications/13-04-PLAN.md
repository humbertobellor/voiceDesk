## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Inngest event payload → email dispatch | contractorId from Inngest event triggers DB load and email send |
| Inngest step → Resend API | Email address and content sent to external email service |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-04-01 | Spoofing | stripe/payment.failed event → send-email-alert | mitigate | Inngest verifies event authenticity via signing key; contractor loaded from DB by contractorId (not from event payload email field); stripePaymentFailureHandler validates contractorId presence before proceeding |
| T-13-04-02 | Information Disclosure | email_address in notification_log.recipient | accept | notification_log is an internal audit table; RLS restricts reads to the contractor's own rows; email_address is contractor-supplied data (their own address) |
| T-13-04-03 | Denial of Service | Inngest retry loop on sendEmail permanent failure | mitigate | retries: 3 on stripe-payment-failure function; retries: 5 on retell-notify-dispatch; both have onFailure handlers with structured logging; Resend configuration errors (missing env var) return success=false on first call, no retry needed |
| T-13-04-04 | Repudiation | notification_log rows with channel='email' | mitigate | Every email attempt writes a log row with status='pending' before send, updated to 'sent'/'failed' after — full audit trail; payment failure emails log with call_id=null (D-18) |
| T-13-04-05 | Tampering | NEXT_PUBLIC_APP_URL in email links | accept | NEXT_PUBLIC_APP_URL is a build-time env var set by the operator; email links (dashboard/calls, settings/account) are constructed server-side in Inngest steps; no user input in URL construction |
</threat_model>
