## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → PATCH /api/notifications/mark-all-read | Mark-all-read mutation endpoint — contractor_id from session, never from body |
| Browser → PATCH /api/notification-settings | Email settings mutation endpoint — contractor_id from session, never from body |
| Browser → Realtime subscription | Supabase Realtime validates contractor_id via RLS on app_notifications table |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-W0-01 | Spoofing | Auth tokens in session | mitigate | Phase 14 uses getUser() from Supabase auth; invalid/expired tokens return 401. No token passed in request body. |
| T-17-W0-02 | IDOR | Mark-all-read endpoint | mitigate | contractor_id derived from session via getUser() lookup; WHERE clause scoped to contractor_id. Request body ignored. |
| T-17-W0-03 | IDOR | Notification settings endpoint | mitigate | contractor_id derived from session; RLS enforces row isolation on notification_settings table. |
| T-17-W0-04 | Information Disclosure | Realtime badge count | mitigate | Supabase Realtime uses JWT authentication; RLS on app_notifications ensures only contractor's notifications are subscribed. |
</threat_model>
