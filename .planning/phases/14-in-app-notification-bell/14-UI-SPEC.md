## Component Inventory

### Bell Icon (Sidebar Header & BottomTabBar)

**Placement:**
- **Desktop:** Right-aligned in Sidebar logo row (the `h-16` div containing Mic icon + "VoiceDesk" text). Icon appears to the right of text with `ml-auto`.
- **Mobile:** BottomTabBar gains a 4th tab (alongside Calls, Leads, Settings) that triggers the notification popover.

**Icon:**
- `Bell` from lucide-react (standard outline bell icon)
- Color: `#94A3B8` (text-secondary) by default; `#F97316` (accent) when `unreadCount > 0`
- Size: 20px × 20px (lucide default w-5 h-5)

**Badge (Unread Count):**
- Appears only when `unreadCount > 0`
- Style: numeric badge with orange background (`bg-[#F97316]`) positioned at top-right of icon
- Badge text: white, 10px font-weight 600, numeric count (e.g., "1", "5", "12+")
- Badge size: 16px × 16px circle or pill (multiples of 4; changed from 20px)
- Implementation: small `<span>` with absolute positioning

### Notification Bell Popover

**Trigger:** Click bell icon in Sidebar or tap Bell tab in BottomTabBar

**Popover (Radix UI Popover component):**
- `@radix-ui/react-popover` (already locked in STATE.md; must be installed if not present)
- Width: 360px or 380px (card width, consistent with app layout)
- Max height: 500px (scrollable if > 50 notifications)
- Background: `#1E293B` (secondary surface)
- Border: 1px solid `#334155` (border-default)
- Border radius: `rounded-lg` (8px)
- Shadow: subtle (Radix default or custom drop shadow)

**Popover Header (inside popover):**
- Text: "Notifications" (bold, 16px, weight 600)
- Button: "Mark all read" (right-aligned in header row)
  - Button text: 12px, weight 400
  - Button color: `#F97316` (accent), underline on hover
  - Button behavior: optimistic unread count update → HTTP PATCH call → Realtime confirmation

**Popover Feed (notification rows):**
- Max rows shown: 50 most recent notifications
- Scroll: auto-scroll if > 50 rows
- Row height: ~56px per notification (title + body excerpt + timestamp)

**Notification Row Layout:**
```
| [colored border] | Title (bold)        | [time]
                   | Body excerpt        |
```

- **Left border:** 4px solid, color-coded by event_type
  - `emergency` → `#EF4444` (red)
  - `lead` → `#F97316` (orange)
  - `system` → `#64748B` (slate)
- **Row padding:** 8px vertical, 8px left (after border), 8px right (multiples of 4; changed from 12px)
- **Row border-bottom:** 1px solid `#334155` (divider between rows)
- **Title:** event_type + context (e.g., "New lead — HVAC repair"), bold (weight 600), 14px, truncate to 1 line
- **Body:** caller phone + appointment status or issue summary, regular (weight 400), 14px, gray (`#94A3B8`), truncate to 1 line with ellipsis
- **Timestamp:** relative time ("3 minutes ago"), 12px, weight 400, text-secondary color (`#94A3B8`)

**Empty State (when unread count = 0 after mark-all-read, or when no notifications exist):**
- Centered message: "All caught up" or "No notifications yet"
- Copy: minimal, dark-themed, consistent with app style
- Padding: 48px vertical, 24px horizontal
- Icon: optional (inbox-zero illustration or simple notification icon, muted color)

**Popover Hover/Focus States:**
- Row hover: subtle background tint (`#0F172A` darker shade or `rgba(255,255,255,0.05)`)
- "Mark all read" button: underline on hover, cursor pointer

### Email Section in Notification Settings Form

**Card Container:**
- Match existing SMS/WhatsApp card CSS: `bg-[#1E293B] border border-[#334155] rounded-xl p-6 mb-4`
- Position: top of form (above SMS card)
- Title: "Email Notifications"

**Card Header (first row):**
- Icon: Envelope (lucide-react `Mail` icon), 20px
- Label: "Email Notifications"
- Checkbox toggle: "Enable email alerts" (right-aligned)
  - Label text: 14px, weight 400
  - Checkbox size: 18px × 18px, accent color `#F97316` when checked

**Card Body (collapse/expand based on checkbox):**
- Email address input field
  - Label: "Email address"
  - Input type: `<input type="email">`
  - Placeholder: "your@email.com"
  - Input CSS: match SMS phone input styling (`bg-[#0F172A] border border-[#334155] rounded-lg px-4 py-2 text-sm`)

  - Value: nullable — empty string saved as `null` to DB

**Form Submission:**
- "Save" button (existing, no changes)

- Error handling: inline error message below email input if validation fails

## Interaction Flows

### Unread Count & Real-Time Updates

1. **On mount:** Query `app_notifications` for unread count (`is_read = false`). Display badge if count > 0.
2. **Realtime subscription:** Subscribe to Supabase Realtime INSERT events on `app_notifications` table. On each insert, increment unread count locally and update badge.
3. **Popover open:** Fetch 50 most recent notifications (paginated, `ORDER BY created_at DESC LIMIT 50`). Cache via React Query `useNotifications`.
4. **Mark all read:** Click "Mark all read" → optimistic unread count = 0 → PATCH `/api/notifications/mark-all-read` → UPDATE `app_notifications` SET `is_read = true, read_at = NOW()` where `is_read = false`. Persist across browser sessions; confirmed by Realtime or next mount.

### Email Settings Integration

1. **Form display:** Email card renders at top of NotificationSettingsForm.
2. **Toggle behavior:** Checkbox "Enable email alerts" controls visibility of email input field (optional collapse).
3. **Input validation:** HTML5 email validation (`type="email"`) — no custom regex required.
4. **Save flow:** Form submit calls `useUpdateNotificationSettings` mutation with `notify_email_enabled` + `email_address` payload. PATCH endpoint already wired (Phase 13). Toast or inline feedback on success/error.

### Notification Bell Placement Interaction (Desktop vs Mobile)

**Desktop (Sidebar):**
- Bell icon always visible in logo row (right-aligned with `ml-auto`)
- Click opens popover to the right of the sidebar
- Popover closes on click-outside or Escape key

**Mobile (BottomTabBar):**
- 4th tab labeled "Notifications" (or icon-only, tapping opens popover)
- Popover may be sheet-style (full height, sliding up) instead of dropdown
- Popover closes on click-outside or back button

## Known Constraints & Dependencies

1. **@radix-ui/react-popover:** Radix UI is the official shadcn/ui popover dependency; locked in STATE.md as a core design system decision. No separate registry vetting required — this is a first-party dependency of shadcn/ui.
2. **No schema migrations required** — Phase 12 created `app_notifications` with RLS; Phase 13 added email columns. Phase 14 only implements the UI and Inngest write step.
3. **Relative time formatting:** Use `formatDistanceToNow` from `date-fns` (already installed) with `{ addSuffix: true }` option.
4. **Hardcoded colors until Phase 16:** Phase 16 Design System Sweep will replace all hex values with CSS variables (`@theme {}` block in Tailwind v4). For Phase 14, use exact hex values from tailwind.config.ts.
5. **Duplicate header removal:** Delete the `<h1>Notifications</h1>` from NotificationSettingsForm component — the Server Component `settings/notifications/page.tsx` owns the canonical heading.
