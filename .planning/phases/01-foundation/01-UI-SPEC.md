# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Foundation. Generated by gsd-ui-researcher.
> All fields pre-populated from CONTEXT.md (D-01 through D-15), RESEARCH.md (Standard Stack),
> and REQUIREMENTS.md. No unanswered questions remained; zero user prompts were needed.

---

## Scope

Phase 1 delivers four UI surfaces:

1. **Auth pages** — `/auth/login` (Google OAuth prominent + email/password secondary), `/auth/signup`
2. **Phone capture step** — `/setup/phone` (required post-OAuth/signup gate before dashboard)
3. **Dashboard shell** — Layout with sidebar nav (Calls / Leads / Settings sub-items), empty states for all sections, "Complete Setup" banner
4. **"Complete Setup" banner** — 4-step mini-progress indicator, always visible in Phase 1

Phase 1 does NOT deliver: call/lead data tables, recordings playback, agent config form, billing pages (Phases 6 and 7).

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Tailwind Class | Usage |
|-------|-------|---------------|-------|
| xs | 4px | `gap-1`, `p-1` | Icon gaps, badge padding, inline element separation |
| sm | 8px | `gap-2`, `p-2` | Compact row padding, form field internal spacing |
| md | 16px | `gap-4`, `p-4` | Default element spacing, input padding, card body |
| lg | 24px | `gap-6`, `p-6` | Section padding, card padding, form group spacing |
| xl | 32px | `gap-8`, `p-8` | Layout column gaps, page content padding |
| 2xl | 48px | `gap-12`, `py-12` | Major section breaks, auth card vertical centering |
| 3xl | 64px | `gap-16`, `py-16` | Page-level spacing (auth page vertical padding on desktop) |

Exceptions:
- Touch targets (buttons, nav items on mobile): minimum 44px height — use `min-h-[44px]` even if visual height is shorter
- Sidebar nav items: 48px height on desktop (`h-12`), 44px on mobile bottom tab bar (`h-11`)
- "Complete Setup" banner: 64px height (`h-16`) to ensure it reads as a persistent attention element

### Accent Reserved For (explicit list — accent is NOT used on all interactive elements)

The orange accent (`#F97316`) is reserved for exactly these elements in Phase 1:

1. Primary CTA button background — "Continue with Google" button, "Continue" on phone capture
2. Active sidebar nav item — left border indicator (4px) and text color for the currently active route
3. "Complete Setup" banner background — the banner uses a muted orange tint (`#F97316` at 15% opacity over `#1E293B`) with orange text and orange progress step fill
4. Progress step fill dots in the "Complete Setup" 4-step indicator (filled = orange, pending = `#334155`)
5. Focus ring on form inputs — `ring-[#F97316]` when input is focused

Accent is NOT used on: secondary buttons, nav items (inactive), card backgrounds, headings, body text, or borders (except focus ring).

## Interaction Contracts

### Form Validation Behavior

| Phase | Behavior |
|-------|---------|
| Before first submit | No validation messages shown. Fields render with default border `#334155`. |
| On submit (error) | All fields validate simultaneously. Error messages appear below each failing field in `text-[#EF4444]` 14px. Field border changes to `border-[#EF4444]`. Focus moves to first error field. |
| After first submit failure | Switch to `mode: "onChange"` — inline validation clears error immediately when field becomes valid. |
| On submit (loading) | Button disabled. Label replaced by `Loader2` spinner (Lucide, 16px, `animate-spin`). Other form fields remain enabled (do not disable entire form). |
| On submit (success — auth) | Button remains in loading state. Page redirects (no client-side success toast — redirect is the confirmation). |
| On submit (success — phone capture) | Button remains in loading state. Redirect to `/dashboard`. |
| On submit (server error) | Loading spinner removed. Error toast appears at top of card: `bg-[#EF4444]/10 border border-[#EF4444]/30 text-[#EF4444] rounded-lg p-3 text-sm`. |

### Loading States

| State | Visual |
|-------|--------|
| Page load (dashboard layout) | Sidebar renders immediately (static Server Component). Main content area shows skeleton: 2 grey rounded rectangles (`bg-[#334155] animate-pulse`) — one for banner (64px), one for page content (240px). |
| Auth page initial load | No loading state needed — pages are Server Components that render immediately. |
| Google OAuth redirect | Button becomes disabled + spinner after click. User sees browser navigation. No custom loading UI needed. |
| Phone capture submission | Button spinner (described above). |

### Focus Management

- Tab order follows DOM order (form fields top-to-bottom, then submit button).
- Focus ring: `ring-2 ring-[#F97316] ring-offset-2 ring-offset-[#1E293B]` on all interactive elements.
- After form error, focus moves to the first field with an error via `setFocus()` from react-hook-form.
- Modal/dialog focus trap: Not needed in Phase 1 (no modals).

### Navigation Active States

- Active route determined by `usePathname()` in `Sidebar.tsx` (Client Component).
- `/dashboard` → "Dashboard" nav item active (if added) — or no active item if only 3 main items exist.
- `/calls` or `/calls/*` → "Calls" active.
- `/leads` or `/leads/*` → "Leads" active.
- `/settings/*` → "Settings" active AND the matching sub-item active.
- Active state: orange left border + `text-[#F8FAFC]` + `bg-[#1E293B]`.
- Hover state (inactive item): `bg-[#1E293B] text-[#F8FAFC]` (no orange border, no orange text).

## Accessibility Baseline (WCAG 2.1 AA)

| Requirement | Implementation |
|-------------|---------------|
| Color contrast (normal text) | All text combinations verified AA or better — see Color table above |
| Color contrast (large text / UI components) | Orange on navy (`#F97316` / `#0F172A`): 5.6:1 — PASS AA for UI components (3:1 minimum) |
| Keyboard navigation | All interactive elements reachable via Tab. Focus ring always visible (never `outline-none` without a custom ring replacement). |
| Screen reader labels | All `Input` components paired with `Label` via `htmlFor`. Google OAuth button has visible text label (not icon-only). Icon-only elements (show/hide password toggle) have `aria-label`. |
| Form errors | Error messages use `role="alert"` via `aria-live="polite"` container OR are associated with fields via `aria-describedby`. react-hook-form's `formState.errors` is read aloud by screen readers when messages are rendered in the DOM. |
| Auth page landmark | `<main>` wraps the auth card. `<nav>` wraps the sidebar. `<header>` wraps the logo area in the sidebar. |
| Touch target size | Minimum 44px on all interactive elements (verified via `min-h-[44px]`). |
| Dark mode | Deferred to v2 (CONTEXT.md deferred). All surfaces use the dark navy theme as the single mode. |
| Reduced motion | Loading spinners use `animate-spin`. Add `@media (prefers-reduced-motion: reduce) { .animate-spin { animation: none; } }` in global CSS to halt spinner for users with this preference. |
| Language attribute | Root `<html lang="en">`. Phase 6 may update this based on contractor's preferred UI language — deferred. |
