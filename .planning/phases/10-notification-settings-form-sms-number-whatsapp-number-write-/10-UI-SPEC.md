## Page Structure

The page follows the canonical settings page pattern established by `settings/calendar/page.tsx`:

```
Server Component (page.tsx)
  └── fetches notification_settings row for authenticated contractor
  └── passes props to NotificationSettingsForm ('use client')

NotificationSettingsForm
  ├── Page header (h1 + subtitle + border-b divider)
  ├── Section 1: SMS channel card
  │   ├── Section heading (icon + label + enable checkbox)
  │   └── sms_number input field (shown always, disabled when toggle is OFF)
  ├── Section 2: WhatsApp channel card
  │   ├── Section heading (icon + label + enable checkbox)
  │   └── whatsapp_number input field (shown always, disabled when toggle is OFF)
  ├── Section 3: Telegram channel card
  │   ├── Section heading (icon + label + enable checkbox)
  │   ├── State A — connected: green status banner + Unlink button
  │   └── State B — not connected: deep-link instructions
  ├── Section 4: Event type toggles card
  │   ├── notify_on_lead checkbox
  │   ├── notify_on_emergency checkbox
  │   └── notify_on_general_inquiry checkbox
  ├── Feedback banner (success or error — shown after save attempt)
  └── Save Settings button
```

## Component Specifications

### Page Header

Exact pattern from calendar/phone settings pages:

```tsx
<div className="mb-6">
  <h1 className="text-xl font-semibold text-[#F8FAFC] mb-1">Notifications</h1>
  <p className="text-sm text-[#94A3B8]">
    Configure how and where you receive call alerts.
  </p>
  <div className="border-b border-[#334155] mt-6" />
</div>
```

### Channel Section Card

Each channel (SMS, WhatsApp, Telegram) is a card using the LanguageSettingsForm card pattern:

```
bg-[#1E293B] border border-[#334155] rounded-xl p-6 max-w-[480px] mb-4
```

Card header row: icon (16px, `text-[#64748B]`) + section label (`text-sm font-semibold text-[#F8FAFC]`) + enable checkbox aligned `justify-between`.

### Phone Number Input Fields

```
w-full px-4 py-2 bg-[#0F172A] border border-[#334155] rounded-lg text-[#F8FAFC] text-sm
focus:outline-none focus:ring-2 focus:ring-[#F97316] focus:border-transparent
placeholder:text-[#64748B]
disabled:opacity-50 disabled:cursor-not-allowed
```

- Placeholder: `+1 (305) 555-1234` (from D-04 / specifics)
- Type: `tel`
- inputMode: `tel`
- When channel toggle is OFF: input is `disabled` and visually dimmed (`opacity-50`)
- Validation error appears below the field: `<p role="alert" className="mt-2 text-sm text-[#EF4444]">{message}</p>`

### Enable/Disable Toggle Checkboxes (per channel)

Pattern from LanguageSettingsForm:

```tsx
<input type="checkbox" className="w-4 h-4 accent-[#F97316]" />
```

Wrapped in `<label className="flex items-center gap-2 cursor-pointer">`.

### Event Type Toggle Checkboxes

Same checkbox pattern. Three rows inside a card:
- "New leads" — `notify_on_lead`
- "Emergencies" — `notify_on_emergency`
- "General inquiries" — `notify_on_general_inquiry`

Each row: `flex items-center justify-between py-3 border-b border-[#334155] last:border-0`. Label left, checkbox right.

### Telegram — Connected State

```
bg-[#16A34A]/10 border border-[#16A34A]/30 text-[#16A34A] rounded-lg p-3 text-sm
```

Content: green dot (`w-2 h-2 rounded-full bg-[#16A34A]`) + "Telegram connected" text + "Unlink" button.

Unlink button: `border border-[#EF4444] text-[#EF4444] hover:bg-[#EF4444]/10 px-4 py-2 rounded-lg text-sm min-h-[44px] transition-colors`. This is an outline destructive button — NOT filled red.

### Telegram — Not Connected State

```
bg-[#1E3A5F]/40 border border-[#3B82F6]/30 text-[#93C5FD] rounded-lg p-3 text-sm
```

Content: Instructions text + deep-link as a styled anchor (`text-[#F97316] underline`).

Deep-link format: `https://t.me/voiceDeskTelBot?start={contractorId}` — opens in new tab (`target="_blank" rel="noreferrer"`).

### Feedback Banner (post-save)

Success:
```
bg-[#16A34A]/10 border border-[#16A34A]/30 text-[#16A34A] rounded-lg p-3 text-sm mb-4
role="status"
```
Content: "Settings saved."

Error:
```
bg-[#EF4444]/10 border border-[#EF4444]/30 text-[#EF4444] rounded-lg p-3 text-sm mb-4
role="alert"
```
Content: "Failed to save settings. Please try again." (generic) or specific API error message if returned.

Banner appears immediately above the Save button. Auto-dismiss the success banner after 3000ms. Error banner persists until the next save attempt.

### Save Button

Primary submit — exact match to LanguageSettingsForm save button pattern:

```
bg-[#F97316] text-[#0F172A] hover:bg-[#F97316]/90 min-h-[44px] font-semibold
px-6 py-2 rounded-lg transition-colors
disabled:opacity-50 disabled:cursor-not-allowed
```

Loading state: `<Loader2 className="w-4 h-4 animate-spin" />` replaces label text. Button remains disabled while loading. Label: "Save Settings" (resting), spinner only (loading).

## Interaction Contracts

### Phone Number Validation

- Validation fires on submit only (not on blur, not on change)
- Use `parsePhoneNumber(value, 'US')` from `libphonenumber-js`
- If invalid: show inline error `<p role="alert">` below the field; focus the invalid field; do NOT submit
- If valid: normalize to E.164 (`+13055551234`) before sending to API
- Empty string is valid (user clearing the field to remove the number) — no error shown for empty

### Toggle Interactions

- Enable toggle OFF → phone number input becomes `disabled` immediately (no save required)
- Enable toggle OFF does not clear the stored number — only the enable flag is toggled
- Telegram enable toggle OFF: hides unlink/setup section; channel is disabled in dispatch
- No unsaved-changes guard — form follows the single Save button contract (D-05)

### Unlink Telegram

- Unlink button triggers `POST /api/notification-settings/telegram/unlink`
- Button shows loading state (`disabled` + spinner) during the request
- On success: Telegram section switches to "Not connected" state; `notify_telegram_enabled` toggle set to OFF in local state
- On error: inline error message below the Telegram card (`role="alert"`)
- Unlink does NOT require Save — it fires its own API call immediately
- Confirm dialog: none — the action is low-risk (re-linking via bot requires 1 click) and the existing destructive-outline button styling provides sufficient visual warning

### Save All

- Save button submits all fields together: `sms_number`, `whatsapp_number`, `notify_sms_enabled`, `notify_whatsapp_enabled`, `notify_telegram_enabled`, `notify_on_lead`, `notify_on_emergency`, `notify_on_general_inquiry`
- Phone number validation runs client-side before the PATCH request
- On `200 OK`: show success banner; invalidate `notification-settings` React Query cache
- On non-200: show error banner with API error message or generic fallback
- Form does not reset on success — values remain as saved

## Accessibility

- All inputs have associated `<label>` elements with matching `htmlFor` / `id`
- Error messages use `role="alert"` so screen readers announce them on insert
- Success banner uses `role="status"` (polite announcement)
- Unlink button has `aria-label="Unlink Telegram account"` (icon-adjacent button)
- Loading states: buttons use `aria-disabled` in addition to the `disabled` attribute
- Telegram deep-link anchor: `target="_blank"` includes `rel="noreferrer"` and visible "opens in new tab" context
