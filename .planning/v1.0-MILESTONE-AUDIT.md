## Blockers

### BLOCKER-01: No notification settings UI — SMS and WhatsApp never fire

**Affected:** NOTIF-01, NOTIF-02, EMRG-03

`settings/notifications/page.tsx` renders `<EmptyState>` only. `notification_settings.sms_number` and `whatsapp_number` columns have no write path in the application — account creation inserts an empty row (comment in `create-account/route.ts:112` says "empty; populated in Plan 06 / Phase 5"). That never happened.

`retell-notify-dispatch.ts` checks:
```typescript
const shouldSendSms = settings?.sms_number != null && ...   // always false
const shouldSendWhatsApp = settings?.whatsapp_number != null && ...  // always false
```

Every contractor has `sms_number = NULL`. SMS never fires. WhatsApp never fires. Emergency channel coverage (EMRG-03) is Telegram-only.

**Fix:** Build `NotificationSettingsForm` with `sms_number` and `whatsapp_number` phone inputs. Wire to server action. Render in `settings/notifications/page.tsx`.

**Additional blocker for WhatsApp:** `WHATSAPP_CONTENT_SIDS` in `src/lib/notifications/whatsapp.ts` still has placeholder values (`HXplaceholder_new_lead`, `HXplaceholder_emergency`). Real WABA-approved Content SIDs required before WhatsApp can send.

---

### BLOCKER-02: Stripe Customer Portal button never renders

**Affected:** BILL-02

`src/app/(dashboard)/settings/account/page.tsx:20`:
```typescript
// BUG — useState initializer, Promise discarded
const [loaded, setLoaded] = useState(() => { loadSubscription() })

// FIX
useEffect(() => { loadSubscription() }, [])
```

`loaded` stays `false`, `subscription` stays `null`. The Customer Portal link is never rendered. Contractors cannot self-serve plan changes, payment method updates, or cancellation without contacting support.
